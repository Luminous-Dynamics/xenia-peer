# Release Evidence Freshness Checks

Status: post-RC1 hardening.

RC1 evidence is historical evidence for the tagged RC1 release snapshot. It should not be regenerated against every later post-RC1 commit, because ordinary documentation or tooling changes can legitimately change source archive checksums, dashboard HEAD identity, and archive inventory.

## Current checker

`scripts/check-release-evidence-freshness.py` verifies:

- required RC1 evidence files exist
- committed RC1 evidence does not contain obvious local path or identity leaks
- release readiness gates still pass
- validation still passes

It intentionally does not rewrite committed RC1 evidence.

## Why historical evidence is not regenerated by default

The RC1 tag is the release snapshot. Evidence generated for that snapshot should remain stable and auditable. Regenerating the same RC1 evidence after later commits would blur the difference between release evidence and current-development evidence.

## Future improvement

Future non-historical evidence generators may add explicit `--check` modes for evidence that is meant to track the current checkout.

A future checker may support modes such as:

- `--historical`: verify required release evidence inventory and hygiene
- `--current`: regenerate current-checkout evidence and fail on diffs
- `--tag <tag>`: verify evidence against a detached release tag

For now, the safe default is historical inventory and hygiene verification.
